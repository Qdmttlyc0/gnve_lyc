# Проект: GNetVulnEye (Рабочее название)

## 1. Проблемное поле
**Контекст:** При аудите локальной сети администраторы часто получают «сырые» данные (IP-адреса, MAC-адреса и открытые порты). 
**Трудность:** 
* Чтобы понять, где принтер, а где уязвимый сервер, приходится вручную сверять данные из разных программ (сканеров, консольных утилит, любительских проектов).
* Легковесные сканеры делают только мгновенный снимок. Если устройство сменило IP-адрес, отключилось или в сеть пробрался посторонний хост — это остается незамеченным, так как нет сохраненной истории предыдущих проверок.
* Результаты сканирования хранятся локально на компьютере одного специалиста. Другой член команды не может посмотреть текущую картину сети, оставить комментарий к устройству или увидеть отчеты коллег.
* Открытые порты сами по себе не говорят о наличии уязвимости. Чтобы понять, что на устройстве стоит старая версия ПО с известными дырами в безопасности (CVE) или стандартный пароль, требуется глубокая ручная проверка, на которую уходит много времени.

**Доказательство:** Проведение интервью с действующими системными администраторами и специалистами по ИБ для подтверждения описанных трудностей.

## 2. Заказчик и целевая аудитория
**Целевая аудитория (пользователи):**
1. **Сетевые администраторы и сисадмины** малого/среднего бизнеса.
2. **Специалисты по информационной безопасности** (для первичного аудита).
3. **Студенты IT-специальностей** (для учебных стендов и лабораторных работ).

**Заказчик:** IT-отдел учебного заведения (Лицей НИУ ВШЭ) / Администрация, заинтересованные в инструменте для мониторинга школьной сети и учебном тренажере.

## 3. Аппаратные и программные требования
**Аппаратные требования (для серверной и клиентской части):**
* Компьютер с 8 ГБ ОЗУ и 4-ядерным процессором.
* Наличие локальной сети с несколькими устройствами (ПК, принтеры, IoT) для тестирования сканера.
* Для тестов допускается использование виртуальных машин (VirtualBox/VMware).

**Программные требования (Стек):**
* **ОС:** Windows 10/11 или Linux.
* **Язык:** Go (Golang).
* **Компилятор:** C-компилятор (MinGW для Windows или GCC для Linux).
* **Фреймворки и библиотеки:** `fyne` (GUI), `gorm` (ORM), `gopacket` (сетевые пакеты).
* **СУБД:** SQLite.

## 4. Функциональные требования (Действия пользователя)
1. **Аутентификация:** Регистрация и вход в систему с разделением прав по RBAC (Администратор — может запускать сканы и удалять данные; Наблюдатель — только просмотр отчетов).
2. **Мультипоточное сканирование:** Запуск ARP/Ping-обхода нескольких подсетей одновременно.
3. **Сбор баннеров:** Получение данных SSH, HTTP-заголовков, TLS-сертификатов, SNMP, mDNS для точного определения типа устройства.
4. **Сохранение истории:** Каждый скан сохраняется в БД.
5. **Сравнение сканов (Дифференциальный анализ):** Автоматическое сравнение нового скана с предыдущим (выявление новых, пропавших устройств или смены IP с подсветкой изменений).
6. **ИБ-аудит:** Проверка найденных версий ПО на наличие известных уязвимостей и тестирование на стандартные пароли.
7. **Визуализация:** Построение интерактивной карты (графа) сети прямо в десктопном приложении.
8. **Экспорт отчетов:** Выгрузка результатов сканирования и аналитики в формат PDF.
9. **Уведомления:** Настройка отправки уведомлений в Telegram-бота при обнаружении важных событий (например, появление нового устройства).
10. **Кроссплатформенность:** Возможность запуска десктопного клиента на Windows и Linux (благодаря Fyne).

## 5. Похожие или аналогичные продукты
1. **Angry IP Scanner / Advanced IP Scanner:** Простые сканеры портов без сохранения истории в БД и глубокого анализа.
2. **Nmap + Zenmap:** Сложный консольный инструмент для профи, нет удобного десктопного GUI с системой аккаунтов и общей базой для команды.
3. **KillerScan:** Легковесный portable EXE без серверной части и базы данных, не поддерживает командную работу и хранение истории.

## 6. Инструменты разработки и база данных
* **Языки программирования:** Go (Golang) + C (через CGO для отрисовки GUI).
* **Среда разработки (IDE):** VS Code / GoLand.
* **Фреймворки:** Fyne (GUI), HTTP-сервер на Go.
* **СУБД:** Реляционная база данных SQLite (встроенная, не требует отдельного сервера).
* **ORM:** GORM (для работы с БД).
* **Сетевые библиотеки:** gopacket.
* **Доступ к БД:** Локальный файл базы данных, создаваемый при первом запуске сервера.

## 7. Этапы разработки
**Этап 1: Проектирование (первая половина ноября)**
* Подтверждение проблемы (интервью). 
* Изучение документации сетевых библиотек (gopacket). 
* Проектирование архитектуры, настройка рабочего окружения. 
* Создание базы данных, настройка CI (Continuous Integration).
* *Результат:* Готовая схема БД, прототип API, настроенное окружение.

**Этап 2: Разработка ядра сканера и сервера (Ноябрь — Декабрь)**
* Написание на Go модуля сетевого сканирования (ARP/Ping-обход).
* Сбор баннеров: SSH, HTTP, TLS, SNMP, mDNS.
* Написание HTTP-сервера на Go и связывание его с БД.
* *Результат:* Работающий сервер, который по команде сканирует сеть и сохраняет результаты в БД.

**Этап 3: Графический интерфейс (Январь)**
* Изучение Fyne. Создание окон авторизации и регистрации.
* Создание главного окна: результаты сканирования, кнопки «Начать скан», «Остановить». Настройка асинхронной работы клиента (чтобы UI не зависал).
* *Результат:* Рабочий интерфейс, позволяющий зайти в систему, запустить сканирование и увидеть результаты.

**Этап 4: ИБ-модуль (Февраль)**
* Добавление проверки баннеров на наличие известных CVE.
* Добавление теста на дефолтные пароли.
* *Результат:* Готовый продукт с модулем информационной безопасности.

**Этап 5: Продвинутые функции (Март)**
* Реализация сравнения двух сканов с подсветкой новых/пропавших устройств.
* Построение графа сети.
* Выгрузка в PDF, фоновый запуск по расписанию, уведомления в Telegram.
* *Результат:* Итоговый продукт.

## 8. Возможные риски и пути их преодоления
* **Риск 1: Нехватка реального оборудования для тестов.** 
  * *Решение:* Развернуть виртуальный тестовый стенд. Использовать VirtualBox/VMware для создания виртуальных машин (Linux с SSH, Windows с открытыми портами).
* **Риск 2: Проблемы с многопоточностью (переполнение ресурсов, падение сервера при сканировании больших сетей).**
  * *Решение:* Использовать пул воркеров (Worker Pool) и семафоры в Go. Ограничить количество одновременных горутин (например, до 50-100) и настроить таймауты.

## 9. Чему придётся научиться в процессе выполнения проекта
* **Работа с сырыми сокетами (Raw Sockets):** Понимание того, как работает сеть на низком уровне (через `gopacket`), как формируются сетевые пакеты.
* **Работа с CGO:** Так как Fyne использует C-библиотеки под капотом, придётся столкнуться с настройкой компилятора C (MinGW/GCC) и понять, как Go взаимодействует с C/C++.
* **Фингерпринтинг:** Написание парсеров для сетевых баннеров для точного определения устройств.
* **Проектирование БД:** Работа с реляционными базами через GORM и написание SQL-запросов для сравнения исторических данных.

## 10. Ресурсы, необходимые для реализации проекта
* **Технические ресурсы:** Компьютер с 8 ГБ ОЗУ и 4 ядрами.
* **Инфраструктура:** Тестовая сеть с несколькими устройствами.
* **Инструменты:** Установленный Go, C-компилятор (MinGW для Windows или GCC для Linux).
* **Библиотеки:** SQLite, gorm, gopacket, fyne.
* **Информационные ресурсы:** Документация по сетям (RFC для ARP, TCP, SNMP, mDNS). Базы данных для парсинга уязвимостей (CVE).

## 11. Образ продукта (Архитектура и функции)
**Архитектура:** Клиент-серверная.
* **Клиент:** Десктопное приложение с графическим интерфейсом (GUI) для Windows/Linux (написанное на Go, фреймворк Fyne).
* **Сервер:** HTTP-сервер на Go, обрабатывающий запросы и выполняющий фоновое сканирование.
* **База данных:** Реляционная БД (SQLite) для хранения аккаунтов, истории сканирований и профилей устройств.

**Масштаб:** Обработка локальной сети.
**Формат распространения:** Установочный пакет (Installer).

**Ключевые особенности:**
* Кроссплатформенность (благодаря Fyne).
* Наличие графического интерфейса с системой аккаунтов (RBAC).
* Полноценный сбор истории сканирований и умное сравнение результатов.
* Интеграция ИБ-аудита (CVE, дефолтные пароли) и уведомлений.
