## 1. Проблемное поле

При аудите сети администраторы получают сырые данные (IP-адреса, MAC-адреса и открытые порты). Чтобы понять, где принтер, а где уязвимый сервер, приходится вручную сверять данные из разных программ (сканеров, консольных утилит, любительских проектов). Также легковесные сканеры делают только мгновенный снимок. Если устройство сменило IP-адрес, отключилось или в сеть пробрался посторонний хост - это остается незамеченным, так как нет сохраненной истории предыдущих проверок. Результаты сканирования хранятся локально на компьютере одного специалиста. Другой член команды не может посмотреть текущую картину сети, оставить комментарий к устройству или увидеть отчеты коллег. Открытые порты сами по себе не говорят о наличии уязвимости. Чтобы понять, что на устройстве стоит старая версия ПО с известными дырами в безопасности или стандартный пароль, требуется глубокая ручная проверка.

Доказательство: проведение интервью с действующими системными администраторами и специалистами по ИБ для подтверждения описанных трудностей.

## 2. Заказчик и целевая аудитория

Целевая аудитория (пользователи): сетевые администраторы и сисадмины малого/среднего бизнеса; специалисты по информационной безопасности (для первичного аудита); студенты IT-специальностей (для учебных стендов и лабораторных работ). Заказчик: IT-отдел учебного заведения (Лицей НИУ ВШЭ) / администрация, заинтересованные в инструменте для мониторинга школьной сети и учебном тренажере.

## 3. Аппаратные и программные требования

Для пользователя: достаточно компьютера 4 гб ОЗУ и 2 ядра. Сеть с несколькими устройствами для тестирования. На диске требуется примерно 35 мб по предварительному расчёту для клиентского приложения. 
Для сервера: необходим Linux-сервер 8 гб ОЗУ и 4 ядра, установленный Go, C-компилятор (т.к требуется MinGW для Windows или GCC для Linux, так как Fyne использует CGO для отрисовки графики), PostgreSQL-сервер (для него выделить надо будет 1 гб диска, чтобы был запас). gopacket вместе с pcap на Linux использует libpcap, на Windows — Npcap
Для разработки: установленный Go, C-компилятор (т.к требуется MinGW для Windows или GCC для Linux, так как Fyne использует CGO для отрисовки графики), PostgreSQL-сервер, gorm, gopacket и fyne фреймворки Go.

## 4. Функциональные требования

Аутентификация: регистрация и вход в систему с разделением прав по RBAC (администратор может запускать сканы и удалять данные; наблюдатель только просмотр отчетов). Мультипоточное сканирование: запуск ARP/Ping-обхода нескольких подсетей одновременно. Сбор баннеров: получение данных SSH, HTTP-заголовков, TLS-сертификатов, SNMP, mDNS для точного определения типа устройства. Сохранение истории: каждый скан сохраняется в БД. Сравнение сканов: автоматическое сравнение нового скана с предыдущим (выявление новых, пропавших устройств или смены IP с подсветкой изменений). ИБ-аудит: проверка найденных версий ПО на наличие известных уязвимостей и тестирование на стандартные пароли. Визуализация: построение интерактивной карты сети прямо в десктопном приложении. Экспорт отчетов: выгрузка результатов сканирования и аналитики в формат PDF. Уведомления: настройка отправки уведомлений в Telegram-бота при обнаружении важных событий (например, появление нового устройства). Возможность оставить комментарий к устройствам другого пользователя при наличии прав на это.

## 5. Похожие или аналогичные продукты

Angry IP Scanner / Advanced IP Scanner: простые сканеры портов без сохранения истории в БД и глубокого анализа. Nmap + Zenmap: сложный консольный инструмент для профи, нет удобного десктопного GUI с системой аккаунтов и общей базой для команды. KillerScan: легковесный portable EXE без серверной части и базы данных, не поддерживает командную работу и хранение истории.

## 6. Инструменты разработки и база данных

Языки программирования: Go + C (через CGO для отрисовки GUI через fyne). IDE: LiteIDE. Фреймворки: Fyne, gopacket, gorm. http-сервер на Go. СУБД: реляционная база данных PostgreSQL. ORM: GORM (для работы с БД). gopacket. Доступ к БД: сервер приложения выступает клиентом к PostgreSQL. NVD api будет использоваться для сопоставления уязимостей с версиями ПО, запросы идут именно туда. Предполагается несколько пользователей для сервера, поэтому требуется многопользовательская БД:
PostgreSQL поддерживает множество одновременных подключений с изоляцией транзакций, в то время как SQLite рассчитан на одного пользователя - при активной командной работе это был бы минус. Также требуются гибкие оконные функции и рекурсивные CTE, которые ещё не так развиты в MySQL.

## 7. Этапы разработки

Этап 1: проектирование (первая половина ноября). Подтверждение проблемы (интервью). Изучение документации сетевых библиотек (gopacket). Проектирование архитектуры, настройка рабочего окружения. Создание базы данных, настройка CI (Continuous Integration). Результат: готовая схема БД, прототип API, настроенное окружение.

Этап 2: разработка ядра сканера и сервера (ноябрь — декабрь). Написание на Go модуля сетевого сканирования (ARP/Ping-обход). Сбор баннеров: SSH, HTTP, TLS, SNMP, mDNS. Написание HTTP-сервера на Go и связывание его с БД. Результат: работающий сервер, который по команде сканирует сеть и сохраняет результаты в БД.

Этап 3: графический интерфейс (январь). Изучение Fyne. Создание окон авторизации и регистрации. Создание главного окна: результаты сканирования, кнопки «Начать скан», «Остановить». Настройка асинхронной работы клиента (чтобы UI не зависал). Результат: рабочий интерфейс, позволяющий зайти в систему, запустить сканирование и увидеть результаты.

Этап 4: ИБ-модуль (февраль). Добавление проверки баннеров на наличие известных CVE. Добавление теста на дефолтные пароли. Результат: готовый продукт с модулем информационной безопасности.

Этап 5: продвинутые функции (март). Реализация сравнения двух сканов с подсветкой новых/пропавших устройств. Построение графа сети. Выгрузка в PDF, фоновый запуск по расписанию, уведомления в Telegram. Результат: итоговый продукт.

## 8. Возможные риски и пути их преодоления

Риск 1: нехватка реального оборудования для тестов. Решение: развернуть виртуальный тестовый стенд. Использовать VirtualBox или VMware для создания виртуальных машин (Linux с открытыми портами, Windows и Linux обычные также для демонстрации и сравнения).

Риск 2: проблемы с многопоточностью (переполнение ресурсов, падение сервера при сканировании больших сетей). Решение: использовать пул воркеров и семафоры в Go. Ограничить количество одновременных горутин (например, до 50-100, точно в момент разработки и тестирования будет известно) и настроить таймауты.

## 9. Чему придётся научиться в процессе выполнения проекта

Работа с сырыми сокетами : как работает сеть на низком уровне (через gopacket). Это потребует понимания того, как формируются сетевые пакеты. Работа с CGO: Так как Fyne использует C-библиотеки, придётся столкнуться с настройкой компилятора C и понять, как Go взаимодействует с C/C++. Фингерпринтинг: научится писать парсеры для баннеров. Необходимо изучить сам фреймворк Fyne и соответственно ознакомиться с документацией по нему. Требуется научиться гибким навыкам: проведить интервью, работать с обратной связью, планировать время.

## 10. Ресурсы, необходимые для реализации проекта

Сеть с несколькими устройствами для тестирования. Установленный Go, C-компилятор (т.к требуется MinGW для Windows или GCC для Linux, так как Fyne под капотом использует CGO для отрисовки графики), SQLite, gorm, gopacket и fyne фреймворки Go. Документация по сетям (RFC для ARP, TCP, SNMP, mDNS). Базы данных для парсинга уязвимостей
Время: в неделю готов тратить 10 часов на проект, при необходимости можно и больше, ранее работал над проектами поэтому готов к нагрузкам по времени.
Компьютер, на котором будет работать серверная часть: Linux-сервер на виртуальном хостинге, 8 гб озу, 4 ядра
Виртуальный тестовый стенд представляет собой виртуальную машину для клиента и сервера, а также уязвимую машину для наглядной демонстрации, обычные Linux и Windows виртуальные машины.
NVD api будет использоваться для сопоставления уязимостей с версиями ПО.

## 11. Образ продукта

Архитектура: Клиент-серверная.
Клиент: Десктопное кроссплатформенное приложение с графическим интерфейсом (написанное на Go, фреймворк Fyne).
Сервер: http-сервер на Go, обрабатывающий запросы и выполняющий фоновое сканирование.
База данных: Реляционная БД (PostgreSQL) для хранения аккаунтов, истории сканирований и профилей устройств.
Масштаб: Обработка локальной сети
Тираж: Распространяется как установочный пакет.

Также при установке требуется согласие на лицензионное соглашение. В тексте этого соглашения будет прописано: «Продукт предназначен исключительно для тестирования сетей, владельцем которых является Пользователь, или на которые Пользователь получил явное письменное разрешение. Пользователь несет полную ответственность за правомерность использования». Дополнительно будет добавлен дисклеймер, на главном экране приложения будет предупреждение о том, что неавторизованное сканирование сетей может нарушать законодательство.
Для разработки и защиты будет использоваться собственный виртуальный стенд


Функции:

1) Аутентификация: Регистрация/вход в систему

2) Мультипоточное сканирование - ARP/Ping-обход нескольких подсетей одновременно.

3) Сбор баннеров SSH, HTTP-заголовков, TLS-сертификатов, SNMP, mDNS для точного определения типа устройства.

4) История: Сохранение каждого скана в БД. Автоматическое сравнение нового скана с предыдущим (выявление новых, пропавших устройств или смены IP).

5) Модуль ИБ-аудита: Проверка найденных версий ПО на наличие известных уязвимостей и тестирование на стандартные пароли.

6) Визуализация: Построение интерактивной карты сети прямо в десктопном приложении.

7) Экспорт и уведомления: Выгрузка отчетов в PDF.

8) Отправка уведомлений в Telegram-бота при необходимости.

9) Разделение прав по RBAC (Администратор - может запускать сканы и удалять данные; Наблюдатель - только просмотр отчетов).

10) Возможность оставить комментарий к устройствам другого пользователя при наличии прав на это
