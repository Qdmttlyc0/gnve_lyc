# Проект: GNetVulnEye

## 1. Проблемное поле

Контекст: при аудите локальной сети администраторы часто получают «сырые» данные (IP-адреса, MAC-адреса и открытые порты). Трудность заключается в том, что чтобы понять, где принтер, а где уязвимый сервер, приходится вручную сверять данные из разных программ (сканеров, консольных утилит, любительских проектов). Легковесные сканеры делают только мгновенный снимок. Если устройство сменило IP-адрес, отключилось или в сеть пробрался посторонний хост, это остается незамеченным, так как нет сохраненной истории предыдущих проверок. Результаты сканирования хранятся локально на компьютере одного специалиста. Другой член команды не может посмотреть текущую картину сети, оставить комментарий к устройству или увидеть отчеты коллег. Открытые порты сами по себе не говорят о наличии уязвимости. Чтобы понять, что на устройстве стоит старая версия ПО с известными дырами в безопасности (CVE) или стандартный пароль, требуется глубокая ручная проверка, на которую уходит много времени.

Доказательство: проведение интервью с действующими системными администраторами и специалистами по ИБ для подтверждения описанных трудностей.

## 2. Заказчик и целевая аудитория

Целевая аудитория (пользователи): сетевые администраторы и сисадмины малого/среднего бизнеса; специалисты по информационной безопасности (для первичного аудита); студенты IT-специальностей (для учебных стендов и лабораторных работ). Заказчик: IT-отдел учебного заведения (Лицей НИУ ВШЭ) / администрация, заинтересованные в инструменте для мониторинга школьной сети и учебном тренажере.

## 3. Аппаратные и программные требования

Аппаратные требования (для серверной и клиентской части): компьютер с 8 ГБ ОЗУ и 4-ядерным процессором; наличие локальной сети с несколькими устройствами (ПК, принтеры, IoT) для тестирования сканера; для тестов допускается использование виртуальных машин (VirtualBox/VMware).

Программные требования (стек): ОС Windows 10/11 или Linux; язык Go (Golang); компилятор C-компилятор (MinGW для Windows или GCC для Linux); фреймворки и библиотеки: fyne (GUI), gorm (ORM), gopacket (сетевые пакеты); СУБД SQLite.

## 4. Функциональные требования (действия пользователя)

Аутентификация: регистрация и вход в систему с разделением прав по RBAC (администратор может запускать сканы и удалять данные; наблюдатель только просмотр отчетов). Мультипоточное сканирование: запуск ARP/Ping-обхода нескольких подсетей одновременно. Сбор баннеров: получение данных SSH, HTTP-заголовков, TLS-сертификатов, SNMP, mDNS для точного определения типа устройства. Сохранение истории: каждый скан сохраняется в БД. Сравнение сканов (дифференциальный анализ): автоматическое сравнение нового скана с предыдущим (выявление новых, пропавших устройств или смены IP с подсветкой изменений). ИБ-аудит: проверка найденных версий ПО на наличие известных уязвимостей и тестирование на стандартные пароли. Визуализация: построение интерактивной карты (графа) сети прямо в десктопном приложении. Экспорт отчетов: выгрузка результатов сканирования и аналитики в формат PDF. Уведомления: настройка отправки уведомлений в Telegram-бота при обнаружении важных событий (например, появление нового устройства). Кроссплатформенность: возможность запуска десктопного клиента на Windows и Linux (благодаря Fyne).

## 5. Похожие или аналогичные продукты

Angry IP Scanner / Advanced IP Scanner: простые сканеры портов без сохранения истории в БД и глубокого анализа. Nmap + Zenmap: сложный консольный инструмент для профи, нет удобного десктопного GUI с системой аккаунтов и общей базой для команды. KillerScan: легковесный portable EXE без серверной части и базы данных, не поддерживает командную работу и хранение истории.

## 6. Инструменты разработки и база данных

Языки программирования: Go (Golang) + C (через CGO для отрисовки GUI). Среда разработки (IDE): VS Code / GoLand. Фреймворки: Fyne (GUI), HTTP-сервер на Go. СУБД: реляционная база данных SQLite (встроенная, не требует отдельного сервера). ORM: GORM (для работы с БД). Сетевые библиотеки: gopacket. Доступ к БД: локальный файл базы данных, создаваемый при первом запуске сервера.

## 7. Этапы разработки

Этап 1: проектирование (первая половина ноября). Подтверждение проблемы (интервью). Изучение документации сетевых библиотек (gopacket). Проектирование архитектуры, настройка рабочего окружения. Создание базы данных, настройка CI (Continuous Integration). Результат: готовая схема БД, прототип API, настроенное окружение.

Этап 2: разработка ядра сканера и сервера (ноябрь — декабрь). Написание на Go модуля сетевого сканирования (ARP/Ping-обход). Сбор баннеров: SSH, HTTP, TLS, SNMP, mDNS. Написание HTTP-сервера на Go и связывание его с БД. Результат: работающий сервер, который по команде сканирует сеть и сохраняет результаты в БД.

Этап 3: графический интерфейс (январь). Изучение Fyne. Создание окон авторизации и регистрации. Создание главного окна: результаты сканирования, кнопки «Начать скан», «Остановить». Настройка асинхронной работы клиента (чтобы UI не зависал). Результат: рабочий интерфейс, позволяющий зайти в систему, запустить сканирование и увидеть результаты.

Этап 4: ИБ-модуль (февраль). Добавление проверки баннеров на наличие известных CVE. Добавление теста на дефолтные пароли. Результат: готовый продукт с модулем информационной безопасности.

Этап 5: продвинутые функции (март). Реализация сравнения двух сканов с подсветкой новых/пропавших устройств. Построение графа сети. Выгрузка в PDF, фоновый запуск по расписанию, уведомления в Telegram. Результат: итоговый продукт.

## 8. Возможные риски и пути их преодоления

Риск 1: нехватка реального оборудования для тестов. Решение: развернуть виртуальный тестовый стенд. Использовать VirtualBox/VMware для создания виртуальных машин (Linux с SSH, Windows с открытыми портами).

Риск 2: проблемы с многопоточностью (переполнение ресурсов, падение сервера при сканировании больших сетей). Решение: использовать пул воркеров (Worker Pool) и семафоры в Go. Ограничить количество одновременных горутин (например, до 50-100) и настроить таймауты.

## 9. Чему придётся научиться в процессе выполнения проекта

Работа с сырыми сокетами (Raw Sockets): понимание того, как работает сеть на низком уровне (через gopacket), как формируются сетевые пакеты. Работа с CGO: так как Fyne использует C-библиотеки под капотом, придётся столкнуться с настройкой компилятора C (MinGW/GCC) и понять, как Go взаимодействует с C/C++. Фингерпринтинг: написание парсеров для сетевых баннеров для точного определения устройств. Проектирование БД: работа с реляционными базами через GORM и написание SQL-запросов для сравнения исторических данных.

## 10. Ресурсы, необходимые для реализации проекта

Технические ресурсы: компьютер с 8 ГБ ОЗУ и 4 ядрами. Инфраструктура: тестовая сеть с несколькими устройствами. Инструменты: установленный Go, C-компилятор (MinGW для Windows или GCC для Linux). Библиотеки: SQLite, gorm, gopacket, fyne. Информационные ресурсы: документация по сетям (RFC для ARP, TCP, SNMP, mDNS). Базы данных для парсинга уязвимостей (CVE).

## 11. Образ продукта (архитектура и функции)

Архитектура: клиент-серверная. Клиент: десктопное приложение с графическим интерфейсом (GUI) для Windows/Linux (написанное на Go, фреймворк Fyne). Сервер: HTTP-сервер на Go, обрабатывающий запросы и выполняющий фоновое сканирование. База данных: реляционная БД (SQLite) для хранения аккаунтов, истории сканирований и профилей устройств.

Масштаб: обработка локальной сети. Формат распространения: установочный пакет (Installer).

Ключевые особенности: кроссплатформенность (благодаря Fyne); наличие графического интерфейса с системой аккаунтов (RBAC); полноценный сбор истории сканирований и умное сравнение результатов; интеграция ИБ-аудита (CVE, дефолтные пароли) и уведомлений.
